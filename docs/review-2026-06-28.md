# Rechoir Repository Review - 2026-06-28

## 검토 요약

Rechoir는 산위의마을교회 성가대의 앵콜곡 추천/기록 도구로 보인다. 현재 구조는 Vite/React 프론트엔드, Netlify Functions API, Google Sheets 저장소, YouTube playlist 동기화로 구성되어 있다. 원래 PRD 방향으로 추정되는 "가볍게 운영 가능한 모바일 중심 내부 도구"에는 잘 맞으며, 별도 DB나 백엔드 프레임워크를 도입하지 않은 판단도 현재 규모에서는 YAGNI에 가깝다.

이번 리뷰에서는 원본 방향을 유지하되 보안 감사, 백엔드 타입 검증, Google Sheets 데이터 무결성, 수동 입력 검증을 우선 보강했다.

## 현재 구조 평가

- `src/pages`: 추천 대시보드, 라이브러리, 곡 상세, 공연 기록, 설정 화면이 페이지 단위로 분리되어 있다.
- `src/components`: 카드, 필터, 태그, 비밀번호 게이트 등 화면 단위 컴포넌트가 작게 나뉘어 있다.
- `src/lib`: API 클라이언트, 추천 점수 계산, 날짜/YouTube 유틸, 데모 데이터가 있다.
- `netlify/functions`: 단일 `api.ts` 라우터와 Google Sheets/Auth/Derived 헬퍼가 있다.
- `Google Sheets`: `songs`, `performances` 시트를 사실상 데이터베이스로 사용한다.

단일 함수 라우터는 현재 API 수가 적어 유지 가능하다. 더 쪼개는 것은 아직 YAGNI다. 다만 데이터 쓰기 경로는 실수 한 번으로 시트가 깨질 수 있어 서버 입력 검증은 필요했다.

## 적용한 수정

- 의존성 보안 업데이트
  - `googleapis`를 `^173.0.0`으로 업데이트했다.
  - `vite`를 `^8.1.0`, `@vitejs/plugin-react`를 `^6.0.3`으로 업데이트했다.
  - `@types/node`를 추가하고 `engines.node >=22.12`를 명시했다.
  - 결과: `npm audit` 취약점이 6건에서 0건으로 감소했다.

- 백엔드 타입체크 추가
  - `tsconfig.functions.json`을 추가했다.
  - `npm run typecheck`가 프론트와 Netlify Functions를 모두 검사하도록 했다.
  - `npm run build`가 `typecheck` 후 `vite build`를 실행하도록 했다.

- API 보안/무결성 보강
  - 비밀번호 비교를 단순 문자열 비교에서 SHA-256 해시 후 `timingSafeEqual` 비교로 변경했다.
  - JSON body가 객체가 아니거나 파싱 실패하면 400을 반환하도록 했다.
  - 곡 추가, 태그 수정, 공연 기록 추가 요청에 최소 서버 검증을 추가했다.
  - YouTube sync에서 API 실패 응답을 명시적으로 에러 처리하도록 했다.
  - 기존 곡 동기화 시 태그를 덮어쓰지 않고 title/url/thumbnail/publishedAt만 변경 감지 후 갱신하도록 했다.
  - Sheets upsert가 체크박스가 있는 빈 행 뒤에 append하지 않도록 첫 빈 `id` 행에 직접 쓰게 변경했다.
  - 체크박스 validation이 있는 `active`, `strings`는 문자열이 아니라 boolean 값으로 쓰도록 변경했다.
  - Playlist sync를 videoId 기준에서 canonical song title 기준으로 변경해 같은 곡의 1부/2부 영상을 하나의 곡과 하나의 날짜별 공연으로 병합하도록 했다.

- 클라이언트 안정성 보강
  - 데모 데이터와 설정의 `localStorage` JSON이 깨져도 앱이 초기화되도록 했다.
  - `songId` 쿼리/경로 일부를 URL 인코딩했다.
  - 수동 곡 추가 시 YouTube ID 형식을 검증하도록 했다.

## 주요 발견

### P1 - 해결됨

- 기존 `npm audit` 결과: high 1건, moderate 5건. 현재 0건.
- 기존 `npm run build`는 `netlify/functions`를 타입체크하지 않았다. 현재 `npm run typecheck`와 `npm run build` 모두 함수 코드를 포함한다.
- 서버가 `body.song`, `body.tags`, `body.performance`를 타입 단언만 하고 신뢰했다. 현재 잘못된 payload는 400으로 거절한다.
- YouTube sync가 기존 곡을 실제 업데이트하지 않으면서 `updated`만 증가시켰다. 현재 변경된 메타데이터가 있을 때만 갱신하고 카운트한다.

### P1 - 남은 리스크

- [src/hooks/useAuth.ts](/Users/jinuk/_DEV/rechoir/src/hooks/useAuth.ts:17): 편집 비밀번호를 `sessionStorage`에 평문 저장한다. 현재 앱은 `dangerouslySetInnerHTML`을 쓰지 않아 직접적인 XSS 표면은 작지만, 공개 배포 서비스라면 서버 발급 단기 토큰 또는 재입력 방식으로 바꾸는 것이 낫다.
- [netlify/functions/lib/auth.ts](/Users/jinuk/_DEV/rechoir/netlify/functions/lib/auth.ts:19): CORS가 `*`이다. 쿠키 인증이 아니라 CSRF 위험은 낮지만, 공개 도메인에서는 `ALLOWED_ORIGINS` 방식의 제한을 검토해야 한다.
- 비밀번호 로그인에 rate limit/lockout이 없다. Netlify 배포 URL이 널리 공개된다면 Edge/Functions 레벨 제한이 필요하다.

### P2 - 관찰 및 제안

- Google Sheets 저장소는 현재 PRD 방향에 적절하다. DB 도입은 아직 과하다.
- 프론트 `calcDerived`와 서버 `calcDerived`가 중복된다. 현재는 작은 중복으로 보는 것이 맞고, 추천/통계 규칙 변경이 잦아질 때만 공유 모듈화를 검토하면 된다.
- 설정은 `localStorage`에 저장된다. 여러 관리자가 같은 추천 가중치를 공유해야 하는 요구가 생기면 Sheets 저장으로 옮긴다.
- 2026-06-28 추가 업데이트: playlist sync 경로는 `getAllSongs()`를 사용하도록 변경해 inactive 곡을 중복 추가하지 않는다.
- 2026-06-28 추가 업데이트: YouTube 영상 제목에서 공연일을 추출해 수동 공연 기록이 없는 플레이리스트 곡도 최소 1회 공연으로 계산한다.
- 2026-06-28 추가 업데이트: 빈 스프레드시트에서도 서버가 `songs`/`performances` 시트와 헤더를 자동 생성하도록 보강했다.
- 2026-06-28 추가 업데이트: 곡 목록 GET 요청마다 플레이리스트를 먼저 동기화하도록 변경하고 API 응답을 `Cache-Control: no-store`로 설정했다.
- 2026-06-28 추가 업데이트: 지정 Google Sheet `rechoir_DB`의 `songs` 데이터가 1001행부터 들어가 상단이 비어 보이는 문제를 실측 확인했다. 원인은 Apps Script가 전체 체크박스 컬럼에 만든 빈 `FALSE` 값과 API append 동작의 조합이었다.
- 2026-06-28 추가 업데이트: 라이브 `songs` 탭의 183개 곡을 2행부터 압축 정리했고, Apps Script는 실제 데이터 행에만 체크박스를 적용하도록 변경했다.
- 2026-06-28 추가 업데이트: 실제 플레이리스트 제목 형식인 `YYYY MM DD`도 공연일로 추출하도록 보강했다.
